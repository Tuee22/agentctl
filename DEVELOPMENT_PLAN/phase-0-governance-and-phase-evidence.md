## Phase Objective

One no-argument `agentctl check` run decides every phase. After verifying its child, the parent publishes one
`PHASE` line per phase ([T.O](development_plan_standards.md#to-output)), judged at stage 1 by
[T.V](development_plan_standards.md#tv-verdict) over the [T.I](development_plan_standards.md#ti-identity) identity
of that phase's closure, then sprint readiness lines and one `selection:` line that agents follow
([T.D](development_plan_standards.md#td-status-and-progression)). The governed plan, ownership manifests, complete
census, ratchet and deletion ledger keep every phase additive and closable from its own prerequisites; a
later-only artifact, citation or failure never enters an earlier verdict or identity
([§ A](development_plan_standards.md#a-well-ordered-constructive-narrative)).

This phase needs Debian Linux only. Foreign-family arms are host-declared modules owned by the earliest phase
whose lane includes that family and are reached lazily through `foundation_host`. A planned absence is unmet work
of the phase that cites it ([T.F](development_plan_standards.md#tf-shared-and-owned-failures)), and present
incompatible code is a deletion-ledger row owned by the phase whose Remaining Work removes it. Every test, killer
child and nested session disturbs nothing the run did not create: it touches only the closed list of
[§ Q](development_plan_standards.md#q-containment-and-user-state-protection) (D-172).

The plan, ownership manifests and deletion ledger make every phase additive and closable from its own
prerequisites, with Linux plus at most one foreign family. A later-only artifact, citation or failure never enters
an earlier verdict or identity, and no mutant or test changes owner to launder a failure
([T.M](development_plan_standards.md#tm-adequacy)).

consumers, and the plan grammar fixes statuses, closing sprints, deletion owners and the hardware-family budget.
Under the run nonce, the guest binding check verifies the dedicated Debian VirtualBox guest's capacity and
dependencies and proves the same-checkout bind mount through source identity, a complete byte census and fresh
nonces in both directions. Its nodes key on the checkout being the `vboxsf` bind mount, as the gate preflight does,

shared-folder binding (D-164). The paths that only the bound checkout executes move into the planned

clean container's run takes their kills and coverage from the guest's current verified run (D-168). The protected

(D-137): its binder nodes keep their ids, import it lazily and are cited there, and no node this phase cites

only bootstrap tests kill move with their killer modules (D-136). Foreign-family arms move behind `foundation_host` into

#### Objective

Only the verified parent publishes verdicts ([T.O](development_plan_standards.md#to-output)). After V1 it prints
one `PHASE` line per phase, judged at stage 1 by V1–V10 ([T.V](development_plan_standards.md#tv-verdict)) over the
[T.I](development_plan_standards.md#ti-identity) identity of that phase's closure, and exits 0 only when every
phase passes.

#### Deliverables

The child gate seals a per-step health record, and the parent verifies it together with every child seal, the
retained report, the interpreter and the census before `cleanup_run_root`. The child stays provisional and its
protected marker rows stay unchanged; the parent withholds child `PHASE` and `EVIDENCE` lines on both streams, and
`verified_child()` gates `publish_phase_verdicts()`, so an unverified run prints
`phase verdicts withheld: <reason>` and exits 1. The planned `src/agentctl/check/verdicts.py` decides V1–V10 per
half against the planned `tests/oracles/phase_verdicts.toml`, takes each half the sealed host does not qualify
from a stored receipt, renders and parses the T.O lines and computes the exit code. It judges V3–V6 and V10 per
half of each lane, with halves of one family sharing kills and coverage (D-168), keeps a failure that arises only
on a foreign family's run out of a linux-lane verdict and gives it to the lowest lane-including phase whose closure
contains what it loads or runs there (D-167), treats a mutant as applicable only on the halves where it is a kill
obligation, so a mutant that only half-declared nodes kill applies only on that half (D-168), and discharges an
owed item only by passing native citations on its half (D-159).

Identity projects manifest, companion and mixed-owner data-file rows to their owners and replaces status cells,
sprint tags, Remaining Work bodies, Gate evidence values and the Validation Hosts table with placeholders, so a
later-only row preserves every earlier identity. Halves replace the legacy lane vocabulary and per-lane
`EVIDENCE`, Gate evidence accepts `current verdict`, and a test node that the host-declaration file declares to
the `linux-clean` or `linux-live` half is evidence, and a killer, only for that half. The spoof matrix yields
`fail` for each
stage-1 spoof (S1–S4, the import, syntax and failed-build kills of S5, S8, S9 and the protected-row part of S10)
and records each stage-2 spoof as unenforced at stage 1
([T.C](development_plan_standards.md#tc-ceiling) C6); the stage-2 checkers of
[Python discipline and gate integrity](phase-1-python-discipline-and-gate-integrity.md) refuse the stage-2 spoofs.
An evidence citation that kills no cited mutant is inadmissible. The receipt and host-lane schemas,
foundation process values and readiness handoffs that this sprint validates are the inputs those verdicts consume.

#### Objective

The gate executes the complete present census without skip, selection or suppression and gives each failure its
[T.F](development_plan_standards.md#tf-shared-and-owned-failures) locus, so a later owned failure never changes an
earlier complete verdict and every earlier verdict depends only on what is owned within its closure
([§ A](development_plan_standards.md#a-well-ordered-constructive-narrative)).

#### Deliverables

Collection equals execution with no skip, xfail or deselection; every present first-party file, test, oracle and
mutant is in the census, and mutant reports, killer handoffs and coverage reports are joined to the run nonce.
Consumer, declaration and integrity scoping compare sets, fail closed on unexplained extras and find the planned
